# M2.0-P2-D 调查与架构说明（组合机械）

- 阶段：M2.0-P2-D
- 基线：`3a99ca2`（P2-C 已验收；开工时工作区 clean）
- 依据：P2-A `Assembly` / `MachineEntity` 定义、P2-B 安装位与旋转、P2-C `MaterialLink`、
  M1.8 机械动力网络、M1.5 空间/建造/拆除系统。
- 结论：现有架构**可以**安全表达组合机械，不需要重写机器/加工/物流/动力系统；
  按任务书允许的最小实现（1×1 正交结构框架 + 由真实零件推导的 Assembly 运行时）实施。

---

## 1. 现状调查

### 1.1 P2-A 已经留下的边界（但没有运行时）

`assets/industrial/runtime-model.ts`：

```ts
export interface MachineEntity {
  readonly entityId: MachineEntityId;   // = MechanicalPart.id（同一身份空间）
  readonly coreId: CoreId;
  readonly placement: Placement;
  readonly ports: readonly PortInstance[];   // P2-A 恒空，P2-B 填充
  readonly assemblyId: AssemblyId | null;    // P2-A 恒 null，组合属于 P2-D
}

export interface Assembly {
  readonly id: AssemblyId;
  readonly memberIds: readonly MachineEntityId[];  // 只有成员表，没有管理逻辑
}

export function createAssembly(id, memberIds): Assembly  // 仅校验非空/唯一
```

P2-A 明确要求：组合**只**维护成员关系，不合并成员身份、不接管成员状态。
P2-D 的运行时以 `Assembly`（id + memberIds）为基础扩展出结构关系/相对位置/边界/需求，
**没有**修改 `createAssembly` 或 `MachineEntity` 的既有语义。

### 1.2 组合对象在现有系统里各自归谁

| 数据 | 现有归属 | P2-D 的处理 |
|:--|:--|:--|
| 核心身份 `MechanicalPart.id` | `MechanicalRegistry`（机械包） | **不变**；Assembly 只引用 |
| 加工状态/进度/缓冲 | `ProductionRuntime`（每核心独立 `MachineState`） | **不碰**；组合前后继续运行 |
| 安装位/接口盒 | `PortRuntime`（P2-B） | **不碰**；成员依旧各自装盒 |
| 物料连接 | `MaterialLinkRuntime`（P2-C） | **不碰**；不自动建链、不误删连接 |
| 动力需求/网络 | `power.ts`（M1.8） | **不碰**；整体需求只是成员额定扭矩求和（查询字段） |
| 空间占用 | `SpatialIndex` + `MechanicalRegistry` | 结构模块作为真实零件占用格子；组合边界只是派生视图 |
| 选择/拆除 | `mechanical.pack` 的 hovered/selected + Delete | 保持单零件选择；组合选中=选中任一成员后识别所属 Assembly |

### 1.3 现有放置与拆除链路（P2-D 结构模块必须复用）

- 机械零件放置：`mechanical.pack` 内部 `place()` 事务；
  依次完成 `SpatialIndex` 校验、Registry 写入、视图创建、库存扣减、`commitTopology()`；
  失败回滚（`rollbackPlace`），不产生半状态。
- 拆除：选中零件 + `Delete` → `remove()` 把零件与视图移除、物品返还；
  P2-B/P2-C 在拆机时由各自运行时的 `sync`/`flush` 处理端口与物料。
- 因此结构模块**不新建**一套放置/拆除逻辑：由 `assembly` 插件调用
  `MechanicalService.placePart()`（P2-D 新增的最小事务入口）放置，
  拆除继续走既有 `Delete` 流程。这保证：
  - 结构模块遵守空间占用/支撑/玩家碰撞规则；
  - 物品只扣一次、只返还一次；
  - 组合关系每帧从真实零件重新推导，拆除后立即解除，不存在“模块已返还但组合还在”。

### 1.4 输入系统的让出模式（P2-B/P2-C 已有先例）

- `FLOOR_MODE_KEY`：floors 插件在 build 之前写入，build/mechanical/ports 各自让出输入。
- P2-D 结构放置模式沿用同一模式：`STRUCTURE_MODE_KEY` 存在时
  build / mechanical / ports 隐藏幽灵并让出输入；`assembly` 插件自己处理
  `P` 切换、悬停格、绿/红幽灵与左键放置。
- 这是最小侵入方式：三个既有系统只增加一处“资源存在即 return”的守卫，
  正常游玩（不按 P）时行为完全不变。

### 1.5 空间系统能表达什么

- 格子坐标（`Placement` + `cellsOf`）、层（`level` + `levelBaseY`）、占地/高度、旋转（0/90/180/270）。
- 1×1 零件旋转不改变占格，这对“成员旋转后组合仍合法”非常关键（场景 G）。
- 组合边界可以直接由成员与结构模块的真实 `cellsOf` + 高度求出，不需要新的空间概念。

## 2. 方案选择（为什么是“1×1 结构框架 + 推导式 Assembly”）

### 2.1 结构模块形态：候选与取舍

| 方案 | 优点 | 缺点 | 结论 |
|:--|:--|:--|:--|
| **A. 可放置的 1×1 结构框架（选中）** | 真实物品/真实占格/真实拆除；用正交相邻天然支持直线、转角、三通等拓扑；不占快捷栏 | 只能表达“相邻”结构，不能跨距离 | ✅ 采用 |
| B. 装在核心安装位上的结构件 | 不用新占格 | 安装位已被输入/输出盒占用；无法表达“核心之间的框架” | ✗ |
| C. 大型框架建筑（build 系统） | 可做大结构 | 不是 MechanicalPart，无法与核心共用同一实体/空间/拆除链路，会另建一套机器数据 | ✗（违反任务书 §三.1） |
| D. 仅 UI 分组/靠近自动成组 | 0 成本 | 明确禁止（§2.2 结构模块必须真实存在；普通相邻 ≠ 组合） | ✗ |

**1×1 正交框架**同时满足：真实物品、真实占格、可拆除返还、有限距离、可扩展
（多个框架串联能摆出任意形状；将来换 1×N 梁只改静态定义，不改运行时语义）。

### 2.2 组合关系来源：候选与取舍

| 方案 | 说明 | 结论 |
|:--|:--|:--|
| **推导式：每帧从真实零件算连通组件（选中）** | 组合关系永远与世界一致；拆除/旋转/合并/分裂自动正确；无“幽灵组合” | ✅ |
| 显式创建/销毁 API（玩家按键建组） | 需要额外 UI 与失败回滚，且容易与世界不一致 | ✗（本阶段不需要） |
| 在 `MachineEntity` 上写 `assemblyId` | 要维护双向一致性，拆解易残留 | ✗ |

推导规则（最小、可解释）：

1. 节点 = 世界里的加工核心 + 结构模块（真实 `MechanicalPart`）；
2. 结构边 = **同层正交相邻**，且至少一端是结构模块；
   核心与核心直接相邻**不**构成结构关系（守住“普通相邻 ≠ 组合”）；
3. 连通、且包含 **≥2 台加工核心** 的组件 = 一个组合机械；单核心组件不叫组合，
   保持原有单机行为；
4. 结构模块可以串联，所以 A 场景一个框架连两台对角核心、B 场景三个框架连三台核心，
   都用同一套规则表达。

### 2.3 Assembly ID：稳定性策略

- 分配 `assembly:<serial>`（P2-A 的稳定 ID 规范），serial 只增不复用；
- 每次重新推导：与既有 Assembly 有任何成员/模块重叠的候选组件，**沿用旧 ID**；
  两个组合被新框架连通合并时保留 serial 最小（最早）的 ID；
- 组件消失 → 组合解除；拆分后较低 partId 的候选组件保留原 ID，另一组分配新 ID；
- 这样“加成员/加框架”不会导致 ID 抖动，只有“拆除/分裂/重建”才会产生新 ID，
  且同一成员永远只属于一个 Assembly（组件天然唯一）。

### 2.4 整体边界与相对位置

- 边界 = 成员核心 + 结构模块的真实 `cellsOf` 并集与最大高度 → 世界 AABB；
- 相对位置/方向 = 每个成员相对“成员中 partId 最小者”的格偏移与旋转差；
- 整体动力需求 = 成员额定 loadTorque 之和（**只读查询**，不参与动力求解）。

### 2.5 整体选择与可视化

- 不改变现有单零件选择：hover/select 仍是 `MechanicalPart.id`；
- 选中零件属于组合时，额外读投影 `ui.selectedAssemblyId`，并画出：
  - **12 条边框光条**表示整体边界（不用半透明罩子，避免遮住机器与结构件）；
  - 成员核心上方琥珀色立柱、结构模块上方青色立柱（区分成员/结构）；
- 世界表现：结构模块是真实网格（灰色上下钢板 + 橙色四角立柱 + 螺栓），
  与深灰机器/砖红炉体明显区分；旋转/拆除后视图随真实 Placement 更新。

### 2.6 物品与获取（明确标记为临时）

- 新物品 `structure_frame`（结构框架，真实物品、背包图标/描述、可堆叠）；
- 锻压机追加配方 `forge-structure-frame`（3 铁锭 → 1 框架，5 秒，追加在配方表末尾）；
- `assembly` 插件开局发放 **4 个**原型结构框架（测试/体验供给）。
- 任务书 §四把“机器获取与解锁”推迟到 P2-E；以上两项属于**临时原型供给**，
  已在代码注释与本文件标注，P2-E 统一调整，不构成最终制造/解锁规则。

## 3. 暂停条件核对（任务书 §六）

| 条件 | 结论 |
|:--|:--|
| Assembly 数据结构无法安全管理成员关系 | 否：组件推导 + 稳定 ID + 唯一成员，已用 16 个运行时测试覆盖 |
| 现有空间系统无法表达组合边界 | 否：`cellsOf` + 高度即可，全部 1×1 零件 |
| 结构模块与核心空间占用根本冲突 | 否：结构模块作为普通机械零件走同一放置事务 |
| 整体选择会破坏现有单机选择 | 否：选择标识不变，只增加只读 `selectedAssemblyId` 与边框视图 |
| 拆解时无法保证核心状态与物料守恒 | 否：拆解只移除结构零件，P2-B/P2-C 运行时状态不动，测试断言连接/端口/缓冲/物料数不变 |
| 组合必须改变加工/动力语义 | 否：不触碰 `ProductionRuntime`、`power.ts`，整体需求只是查询字段 |
| 需要整体移动/整体旋转才能实现目标 | 否：本阶段明确不做，任务书也未要求 |
| 影响未来嵌套/结构扩展的重大架构问题 | 否：结构图模型与 `StructureModuleDef` 可扩展到多格/多形状模块；嵌套组合若将来要做，需要额外规则，但不影响当前设计 |

**无需暂停**；小型、可逆的工程细节（热键 P、边框样式、原型数量/配方）已自行决定并记录。

## 4. 风险与对策

| 风险 | 对策 |
|:--|:--|
| 组合关系与世界状态不同步（拆一半） | 每帧从真实零件推导；拆零件即解除，不留半状态 |
| 结构模块被误当成机器/物流参与 | 运行时节点只认「加工核心 / 结构模块」；动力只认有端口零件；生产只认 machine/transport |
| 拆结构模块误删 P2-C 连接 | 拆解只走 `mechanical.remove()`；`MaterialLinkRuntime` 只对核心端点做校验，结构模块不在链接端点集合中 |
| 整体需求被误解为“合并产能” | `AssemblySnapshot` 只有成员额定扭矩求和；单测断言快照没有 speed/throughput/rate 字段 |
| 成员旋转导致空间数据不一致 | 1×1 旋转不改变占格；运行时按真实 Placement 每帧重算；P2-C 连接按自己的几何规则失效/恢复 |
| 历史验收脚本的新按键/新物品回归 | 新按键仅 P（+结构模式），新物品仅背包/配方末尾；回归 M1.8/P1/P2-B/P2-C 全通过 |
