## 6. `MaterialLink` 与连接规则（摘要）

- 数据用 P2-A 的 `MaterialLink { id, from, to }`；ID 稳定规范（`link:<from>-><to>`）。
- 直通类接口：**严格端口对接**（锚点重合 + 法线相反）。
- 分流/合流：**严格对接或近距定向对接**（≤ 2 m，双方朝向对方）；
  原因是一个安装位只有一个世界锚点，多口模块额外端口无法锚点重合（详见 INVESTIGATION §4）。
- 数量上限由模块定义：输出侧 ≤ `outputs`，输入侧 ≤ `inputs`。
- `status` 分：ok / 缺机器 / 缺接口 / 数量超限 / 几何失效；失效连接保留、恢复后自动继续。
- 物料**从不进入连接**，只在接口盒缓冲/机器缓冲里 → 任何断链/拆机都不会有在途料丢失。

## 7. 物料传输、容量与守恒（摘要）

- 每帧：输入盒 drain → 机器输出 → 输出盒 pull → 连接 stepLinks → 加工 → 产物推溜槽（M1.8）。
- 容量：核心缓冲（4/6/4）、接口盒容量（= 对应安装位容量）、连接 1 件/次、单端口每步最多 1 次转移。
- 传递唯一原语 `PortRuntime.moveOne`：先检查（源有料/目标存在/类型兼容/目标余量）再扣源再写目标，
  检查之后无可失败步骤 → 不重复、不丢失、两端不同时拥有。
- 断电不阻断物料转移；机器不加工时物料停在缓冲。

## 8. 分流 / 合流策略（摘要）

- 分流：每个源端口独立轮询游标；每次推进按游标顺序尝试，成功一条后前移，实现 2 路严格交替；
  目标满载/不可用则跳过，全部堵塞时留在源盒。
- 合流：目标接口盒单缓冲，每次推进最多写入一次，多路按端口组轮询竞争；写前检查容量/类型；
  后到者不写入、物料留在各自源盒；每条入链有独立连接 ID 与 `moved` 读数。

## 13. 性能与已知限制

### 13.1 性能

- 物流推进完全复用现有 `ProductionRuntime.tick`（每帧一次），没有为连接创建定时器/协程；
- 每帧成本：遍历连接（通常个位数）+ 每连接一次几何/端口校验 + 最多一次 `moveOne`；
- 接口盒/连接视图每帧按机器当前 Placement 重算，实体数量与「已装盒数 + 连接数」同阶；
- 真实游戏 1280×720 下验收脚本 500 步 / 约 310 s，FPS 画面稳定（截图与 console 均无异常）。

### 13.2 已知限制

1. **分流/合流的第二路是「近距定向对接」而不是零距离贴合**：一个安装位只有一个锚点，
   多口模块无法让两路都锚点重合；这是任务书允许的最小替代方案（INVESTIGATION §4）。
2. **连接容量固定为 1 件/次物流推进**：当前所有配方都是数秒级，实际瓶颈在加工；
   该值记录在连接读投影里，将来可数据化。
3. **接口盒缓冲在逐帧 drain 下通常同帧清空**：真实游戏很难稳定看到「盒里压着料」的画面
   （P2-B R3 的延续），验收用 `moved` 与机器缓冲读数证明传输。
4. **没有存档**：连接与接口盒状态是内存态（与端口/生产状态一致），存档阶段需要一起序列化。
