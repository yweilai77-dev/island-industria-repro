### 1.3 开局原型套件调整

| 零件 | P2-B | P2-C | 原因 |
|:--|--:|--:|:--|
| 破碎机 / 熔炼炉 | 1 / 1 | **3 / 3** | 合流需要两台同种上游、分流需要两台同种下游 |
| 测试动力源 | 2 | **4** | 三核场景需要 3 个独立动力网络；多给 1 个避免「全部摆出后数量归零」 |
| 其它 | 不变 | 不变 | 轴/齿轮等余量充足 |

> 「数量归零」会触发快捷栏的 `dropUnavailable` 自动解绑；之后玩家再按同一数字键会选中空槽，
> 机械系统让出输入、点击落到普通建造系统。P2-C 的多核场景会一次性摆出全部核心/动力源，
> 因此套件数量必须留 1 件余量。

## 2. `MaterialLink` 运行时数据模型

### 2.1 静态与运行时边界

| | 内容 | 归属 |
|:--|:--|:--|
| 连接数据 | P2-A 的 `MaterialLink { id, from, to }`（from = 输出位端点，to = 输入位端点） | `MaterialLinkRuntime` |
| 传输容量 | 每条连接 1 件 / 次物流推进（`MATERIAL_LINK_CAPACITY`） | 同上 |
| 实时状态 | `active` + `status`（ok / 缺机器 / 缺接口 / 数量超限 / 几何失效） | 派生，不存盘 |
| 累计传递 | 每条连接 `moved` 件数（验收与调试读数） | 同上 |
| 物料本身 | **永远只在接口盒缓冲 / 机器缓冲里**，连接不持有物料 | `PortRuntime` / `ProductionRuntime` |

`MaterialLinkId` 沿用 P2-A 的规范 ID：
`link:<fromEntityId>:<fromSlotId>-><toEntityId>:<toSlotId>`，由 `materialLinkBetween` 生成，
稳定、可 grep、可序列化。

### 2.2 连接建立校验（全部通过才写入；失败不产生任何状态变化）

1. 两端必须是**不同**的真实加工核心（`isProductionMachine` + `coreForPart`）；
2. `from` 必须是输出安装位、`to` 必须是输入安装位；
3. 两端都必须**装了接口盒**，且接口盒的 `fitsSlotRoles` 包含该位角色；
4. 不能重复连接同一对端点；
5. 数量上限：同一输出端口上的连接数 ≤ 该接口盒 `outputs`；同一输入端口上的连接数 ≤ `inputs`；
6. 几何（见 §3）。

### 2.3 连接生命周期

| 事件 | 行为 |
|:--|:--|
| 玩家建链 `J` | 选上游输出接口（源头高亮）→ 悬停下游按 `J` → 校验通过则写入 |
| 玩家解链 `H` | 解除悬停核心上所有端口上的连接（物料不动，仍在缓冲里） |
| 拆接口盒 `Y` | 解除该端口连接；盒子与盒内物料返还库存 |
| 拆核心 | 该核心的接口盒与缓冲交回库存；**引用它的连接被清理** |
| 旋转核心 `U` | 连接保留；几何不成立时 `status=inactive-geometry`，转回后自动恢复 |
| 目标满载/类型不符 | 不传输；物料留在源接口盒（不吞、不丢、不复制） |

## 3. 端口对接与连接建立规则

### 3.1 严格端口对接（直通类接口：基础盒 / 输出盒）

复用 `slotWorldOf` 的世界锚点与法线：

- 两端锚点距离 ≤ 1e-4 m（同一个点）；
- 两端面外法线点积 ≤ −1 + 1e-4（正对）。

这就是「相邻核心必须面对面」的精确表达：例如破碎机 rot 0 的输出锚点 (−3, 8.5) 与
熔炼炉 rot 90 的输入锚点 (−3, 8.5) 完全重合。

### 3.2 近距定向对接（任一端是分流/合流模块时）

- 两端锚点距离 ≤ 2 m；
- 源端口法线朝目标方向（点积 ≥ 0.5，约 60°）；
- 目标端口法线朝源方向（点积 ≥ 0.5）。

原因：一个安装位只有唯一锚点，多口模块的第二路端口无法与它锚点重合。
该规则仍然只依赖现有安装位的世界坐标与朝向，不引入新的空间概念；
第一路通常仍然可以严格对接。

### 3.3 数量上限与安装位角色

- `port.through` / `port.output` / `port.splitter` 只能装在输出位（through 也可以输入位）；
- `port.merger` 只能装在输入位；
- 分流盒 `outputs=2` → 同一输出端口最多 2 条出链；
- 合流盒 `inputs=2` → 同一输入端口最多 2 条入链；
- 超过上限的连接被拒绝（`from-port-full` / `to-port-full`）；
  若玩家换盒导致已有连接超限，连接显示 `inactive-port-limit`，直到玩家解掉多余连接。

## 4. 物料传输、容量与守恒

### 4.1 每帧顺序（`ProductionRuntime.tick`）

```
① 输入接口盒 → 机器输入缓冲（drain，P2-B 已有）
② 机器输出缓冲 → 输出接口盒缓冲（pull，新增）
③ 物料连接：源接口盒 → 目标接口盒（stepLinks，新增）
④ 机器加工（现有状态机）
⑤ 机器产物 → 相邻溜槽（M1.8 行为，未装输出盒时不变）
⑥ 溜槽推进/交接（现有）
```

- 装了输出接口时，产物优先走接口盒；接口盒满才溢出到相邻溜槽。
- 没有输出接口时，⑤ 与 M1.8 完全一致。

### 4.2 容量模型

| 环节 | 容量 |
|:--|:--|
| 核心输入缓冲 | `MechanicalPartDef.buffers.input`（破碎机/熔炼炉 4，锻压机 6） |
| 核心输出缓冲 | `MechanicalPartDef.buffers.output`（4） |
| 输入/输出接口盒缓冲 | 该安装位容量（= 对应核心缓冲容量） |
| 单条 MaterialLink | 1 件 / 次物流推进（`MATERIAL_LINK_CAPACITY`） |
| 单个接口端口 | 每次推进最多参与 1 次转移 |

实际传递量 = min(源缓冲剩余, 连接容量, 目标剩余空间)，任何一环为 0 就不转移。

### 4.3 守恒规则（原子性）

- 唯一传递原语是 `PortRuntime.moveOne`：
  **先完成全部检查**（源有料、目标存在、类型兼容、目标有余量），**再扣源、再写目标**；
  检查之后没有任何可失败步骤。
- 因此不会出现「两端同时拥有」「转移中消失」「复制同一批物料」。
- 接口盒缓冲是单物料类型（与机器缓冲一致）：目标已有另一种物料时不接收。
- 连接本身从不暂存物料：断链/拆盒/旋转/拆机的物料都停在某个接口盒或机器缓冲里，
  重连或重装后自动继续。

### 4.4 断电 / 暂停 / 机器不可用

- 物料转移**不依赖动力**（与溜槽一致）；断电时机器不加工，物料停在机器输入缓冲/接口盒。
- 恢复动力后从原进度继续，不产生重复产物。

## 5. 分流、合流策略

### 5.1 分流（一进二出）

- 分流盒装在上游输出位，缓冲接收机器产物；最多 2 条出链。
- **轮询分配**：`MaterialLinkRuntime` 为每个源端口维护独立游标；
  每次推进按游标顺序尝试该端口的连接，成功一条后游标前移，下一次由另一条先试。
- 「同一接口每次推进最多参与 1 次转移」保证不会一帧把所有料塞给同一个目标。
- 一个目标满载/不可用时，跳过它，物料继续走其它连接；全部连接都堵住时物料留在源接口盒。

### 5.2 合流（二进一出）

- 合流盒装在下游输入位，最多 2 条入链；每个上游连接保留独立连接身份（独立 ID / `moved`）。
- 目标接口盒只有一个缓冲：每次推进最多一次写入，多个上游按端口组轮询顺序竞争；
  后到者发现缓冲满/类型不符时不写入，物料留在自己的源接口盒。
- 不会出现「两路同时覆盖同一缓冲」：写入是单线程顺序的，且写前已做容量/类型检查。

### 5.3 多级产线与同时运行

- 连接按 ID 稳定排序遍历，端口组之间也有轮询游标；多级产线可以在同一帧里逐级推进
  （上游输出盒 → 中游输入盒 → 中游加工 → 中游输出盒 → 下游输入盒）。
- 不引入全局寻路、优先级经济、损耗或磨损。

## 7. 读投影

唯一 GameRead `mechanical` 新增 `links` 字段（与 P2-B 的 `ports` 并列，不新增第二个 read）：

```json
{
  "id": "link:22:slot.crusher.out.px->23:slot.smelter.in.nz",
  "from": { "entityId": 22, "slotId": "slot.crusher.out.px" },
  "to": { "entityId": 23, "slotId": "slot.smelter.in.nz" },
  "capacity": 1,
  "active": true,
  "status": "ok",
  "moved": 2
}
```

`status` 取值：`ok` / `inactive-missing-part` / `inactive-missing-port` /
`inactive-port-limit` / `inactive-geometry`。

## 8. 被否方案

| 方案 | 否决理由 |
|:--|:--|
| 用机械动力 `Connection` 表达物料连接 | 语义完全不同（传动比 vs 物料流向）；P2-A 已明确禁止 |
| 直接用 A 的库存写 B 的缓冲 | 违反「必须经过明确物料转移」；无法做原子性与背压 |
| 连接上挂「在途物料」缓冲 | 断链/拆机时物料会卡在连接里；本阶段要求「失效时物料停留位置明确」，直接不暂存最简单 |
| 相邻即自动连接 | 任务书 §2.2 明确禁止；连接必须是显式关系（J 建立） |
| 分流/合流做成独立放置模块 | P2-A 已把两者定义为安装位模块；改成放置模块会改已验收数据模型，且快捷栏已满 |
| 多口模块全部要求锚点重合 | 几何上不可能（一个安装位只有一个锚点） |
| 每帧按连接创建定时器 | 任务书 §四明确不要无约束定时器；统一在现有 `production.tick` 里推进 |
| 新增第二个 GameRead 暴露 links | 历史 playthrough 会 `state-unavailable`；只扩展现有 read |
