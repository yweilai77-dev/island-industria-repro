## 2. 现有链路复查（P2-C 真正会碰到的部分）

### 2.1 接口盒一个安装位只有**唯一世界锚点**

- 安装位世界坐标由 `assets/industrial/port-slot-world.ts` 的 `slotWorldOf` 派生：
  锚点 = 机器表面中心，法线 = 面外法线，二者都随机器 `Placement.rotation` 变化。
- 每台加工核心只有 1 个输入位（`slot.<core>.in.nz`，容量 4/6）与 1 个输出位
  （`slot.<core>.out.px`，容量 4）。见 `assets/industrial/processing-core.ts`。
- 因此「一个安装位上最多一个盒、一个盒在该槽位只有一个物理位置」。

### 2.2 核心↔核心直连在现有空间系统里**可以**精确表达

两台 1×1 核心相邻时，一个端口的锚点可以精确落在另一个端口锚点上，且法线相反。
关键是要选对下游核心的朝向（输入位在本地 `nz`）：

| 上游 | 下游 | 对接结果 |
|:--|:--|:--|
| 核心 rot 0（输出 px → +X） | 核心在 +X 一格、rot 90（输入 nz → −X） | 锚点重合、法线相反 ✅ |
| 核心 rot 27 0（输出 px → +Z） | 核心在 +Z 一格、rot 0（输入 nz → −Z） | 锚点重合、法线相反 ✅ |

即：**不需要新增任何空间规则**，直接用 `slotWorldOf` 的锚点/法线做「端口对接」判定即可。

### 2.3 但多口模块（分流/合流）**无法**用锚点重合表达

分流盒定义为「1 进 2 出」，合流盒「2 进 1 出」（`assets/industrial/port-module.ts`）。
它们都装在一个安装位上，而一个安装位只有一个世界锚点：

- 分流：第二个下游端口不可能与同一锚点重合；
- 合流：第二路上游端口同理。

**这是本阶段必须先给出「最小替代方案」的地方**（任务书 §三 P2-C-2 明确要求：
先说明问题和最小替代方案，不要创造与现有安装位无关的空间规则）。

### 2.4 物料流向与容量

- 加工状态机（`assets/production/production.ts`）：
  - 输入缓冲单物料类型、整笔消耗；输出缓冲单物料类型、容量 4（锻压机 6/4）。
  - 产物在**周期完成时**才进入输出缓冲；开工即消耗原料（在制物料不在任何缓冲里）。
- `ProductionRuntime`（`production-runtime.ts`）每帧顺序：
  `drain 输入接口盒 → 加工 → 把产物推给相邻溜槽 → 溜槽推进/交接`。
- 溜槽交接（`handoff`）在 P2-B 后必须经输入接口盒；`pushMachineOutputs` 只推给 kind=transport。
- 结论：P2-C 只需在「机器输出缓冲」与「机器输入缓冲」之间加一段
  「输出接口盒 → 连接 → 输入接口盒」，不需要改加工状态机。

### 2.5 物品 / 配方 / 安装 / 拆卸 / 旋转 / 拆机

- 物品：`assets/items/items.ts` 静态定义 + 背包/图标；新增物品只需 ItemId + 定义 + icons。
- 配方：`assets/production/recipes.ts`，锻压机配方是数组，R 键循环；追加在末尾不影响既有顺序。
- 安装/拆卸：`PortRuntime.install/remove`（P2-B），拆卸返还盒子与盒内物料。
- 旋转：P2-B 的 `U` 走 `mechanical.updatePlacement` 事务（校验 → registry → 空间 → 视图 → commit）。
- 拆机：`PortRuntime.sync` 把该机器全部接口盒与缓冲交回库存。
- 结论：P2-C 复用这些事务即可；不需要新实体/新 ID 空间。

### 2.6 读投影

唯一 GameRead `mechanical` 里已有 `ports` 字段；P2-C 再增加 `links` 字段（仍然是同一个 read，
不新增第二个 read，避免历史 playthrough 的 `state-unavailable`）。

## 3. 内容缺口（产品层面必须先解决的依赖）

当前开局原型套件每台加工核心只给 1 台，锻压机也没有「复制加工核心」的配方。于是：

- 「两台上游合流到一台下游」需要 2 台同种上游；
- 「一台上游分流到两台下游」需要 2 台同种下游；
- 三核多级产线需要 3 台核心（现有内容刚好够 1 条，但没有冗余）。

**结论**：P2-C 必须补「获得更多加工核心」的最小途径，否则任务书 §七 的场景 B/C 不可能在真实游戏中搭出来。
本阶段采用两条最小改动（均在授权范围内、不改既有机器行为）：

1. 锻压机新增 3 条**既有锻造工艺**的复制配方（`forge-crusher` / `forge-smelter` /
   `forge-processing-core`），只新增配方数据；
2. 开局原型套件把破碎机/熔炼炉从 1 台提到 3 台、测试动力源从 2 台提到 4 台
   （同时避免「全部摆出去后数量归零、快捷栏绑定被自动解除」导致后续放置落入普通建造模式）。

## 4. 必须说明的两个空间问题与最小替代方案

### Q1：多口模块（分流/合流）的端口几何怎么表达？

**问题**：一个安装位只有一个世界锚点，2 个下游/上游端口不可能同时与它锚点重合。

**最小替代方案（本阶段采用）**：

- 直通类接口（1 进 1 出：基础盒 / 输出盒）继续要求**严格端口对接**：
  锚点重合、法线相反。核心↔核心直连走这条规则。
- 任一端是多口模块（分流 `outputs=2` / 合流 `inputs=2`）时，允许**近距定向对接**：
  两端锚点距离 ≤ 2 m，且两个端口都朝向对方（点积 ≥ 0.5）。
  规则只依赖现有安装位的世界锚点/法线/机器旋转，不引入与安装位无关的新空间概念。

**代价**：分流/合流的第二路连接是「短距、朝向正确」的直连，不再是零距离贴合；
第一路仍然可以严格对接。真实游戏中可以稳定搭出「上游 → 分流 → 两台下游」与
「两台上游 → 合流 → 一台下游」。

### Q2：输出接口盒与输入接口盒是否需要区分？

**问题**：P2-A 只定义了「基础直通盒（1 进 1 出，输入位/输出位都能装）」。

**最小替代方案（本阶段采用）**：

- 保留 `port.through` / `interface_box` 的既有语义（P2-B 已验收，不推翻）；
- 新增 `port.output` 模块 + `output_interface_box` 物品：1 进 1 出，**只能装输出位**；
- 分流/合流盒各自绑定真实物品（`splitter_box` / `merger_box`），只能装在各自角色位。
- 这样「输入接口」与「输出接口」在**模块定义**层面是明确区分的功能类型；
  普通输入接口（只能装输入位的模块）不会自动获得输出能力。

## 5. 本阶段最小实施方案

1. 数据层：3 个新物品（输出/分流/合流盒）+ 6 条新锻压配方（3 盒 + 3 核心复制）；
   `port.output` 模块；`port.splitter`/`port.merger` 绑真实物品；完整性校验同步。
2. `PortRuntime`：增加输出位接口、缓冲读视图、`moveOne`（唯一原子传递原语）。
3. 新 `MaterialLinkRuntime`：连接创建校验（端口/角色/数量/几何）、轮询推进、失效/恢复、
   读投影（含 `moved` 累计传递数）。物料**从不进入连接**，只存在于接口盒缓冲，
   因此断链/拆盒/旋转/拆机都不会有「在途物料」丢失。
4. `ProductionRuntime`：每帧新增「机器输出缓冲 → 输出接口盒 → 连接 →
   输入接口盒 → 机器输入缓冲」两段；未装输出盒时保持 M1.8 的产物推溜槽行为。
5. `port` 插件：输出盒/分流/合流安装（O/K/L）、建链（J）、解链（H）；
   接口盒分色、连接画成铜管、建链源头高亮；拆盒时解除该端口连接并返还物料。
6. 读投影：唯一 `mechanical` 读里新增 `links`。
7. 测试：连接规则、守恒/背压、分流/合流、旋转/拆卸/重连、多级产线、旧系统回归。
8. 真实游戏验收脚本：`scripts/p2c-links.mjs`（场景 A–F + 制造演示），全部真实键鼠操作。

## 6. 结论

1. P2-C 可以在现有架构内完成，不需要改加工状态机、动力网络或机器身份；
2. 唯一需要「最小替代方案」的是多口模块的端口几何——用「严格对接 + 近距定向对接」组合表达；
3. 为了让真实游戏里搭得出多核网络，必须补「加工核心复制」的最小内容；
4. 不进入 P2-D（组合机械整体结构），完成后停止等待验收。
