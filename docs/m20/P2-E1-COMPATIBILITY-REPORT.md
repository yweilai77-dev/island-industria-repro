# M2.0-P2-E1 兼容性报告

- 阶段：M2.0-P2-E1
- 结论：**M1.8 机械动力与生产、P1 八步订单、P2-B 接口盒、P2-C 物流、P2-D 组合机械、既有库存与唯一 GameRead 全部保持并通过回归**。
  兼容成本集中在两项：①开局供给从临时原型套件换成正式起步包；②科技门控生效。两者通过「只加门控入口、不改求解语义」与「旧脚本 legacy 兼容模式」隔离。

---

## 1. 兼容策略

1. **不改已验收系统的语义**：动力网络（单源树状/齿轮比/下垂/过载）、加工状态机、端口/物料连接、Assembly 运行时的数据所有权与求解逻辑一行未改；科技只增加**入口门控**与**配方可见性**。
2. **唯一 GameRead 不破**：没有新增第二个 read；科技快照并入 `mechanical`。
3. **配方身份用 recipeId**：`MachineState.recipeId` 成为权威，`recipeIndex` 仅作兼容字段；配方列表只追加、不重排，历史 11 条下标不变。
4. **旧验收脚本走 legacy 兼容模式**：保留历史套件/槽位/全配方与原有断言，只增加启动步骤。

## 3. 配方身份与顺序（关键兼容点）

- **问题**：解锁集合会随时间变化，若机器只存下标（`recipeIndex`），解锁新配方后可能悄悄指向另一条配方（P2-E0 依赖文档 D3）。
- **实现**：`MachineState.recipeId` 为权威；`activeRecipe` 优先按 ID 解析；`cycleRecipe` 设置新的 ID 与兼容下标；`ensureRecipeSelected` 只在新机器/空选择时兜底。
- **顺序保护**：科技新增 6 条配方全部追加在锻压机列表末尾（11 → 17），历史 11 条顺序/下标不变；全部配方表（13 → 19）只追加。
- **证据**：`tech-recipe-order.test.ts` 16 例，含「先造某配方→解锁新配方→recipeId 不漂移」回归；`production.test.ts` 回绕断言仍按完整表顺序通过。
- **契约同步**：4 个既有测试文件只把「配方数量/列表」扩展为含新增项（不删除、不弱化断言）。

### 4.2 旧脚本迁移（19 个脚本改动，断言未动）

- 新增 `scripts/legacy-mode.mjs`：`page.addInitScript` 注入 `__II_TEST_FLAGS__={progression:'legacy'}` → `play.reload()` → 轮询直到 `tech.mode==='legacy'` **且 16 项历史套件逐项精确相等**（30 s 超时抛错，不静默继续）。
- 迁移方式：入口 `default export` 第一句 `await enterLegacyMode(play)`；m17a 在自身 `07-reload` 后额外 `waitForLegacy`。
- 迁移清单：`playthrough`、`m17a`、`m17b`、`m17c-playthrough/overload/branch-overload/cyclic/reconnect`、`m18-probe`、`m18a-crosslevel`、`m18a2-floors`、`m18c-production`、`m18e-playtest`、`m20-first-order`、`m20c-hud`、`p2b-ports`、`p2c-links`、`p2d-assembly`。
- 未迁移（有理由）：`m18-smoke`（纯启动 smoke，不依赖套件）、`m18-nav`/`m18-zoom-probe`（纯探针）、全部分阶段子模块与 `*-lib`（由入口统一进入 legacy）、`m18-helpers.mjs`（共享库行为未改）。
- **断言未删除/未弱化**：只新增启动/等待步骤；回归结果见测试报告。

### 4.3 legacy 模式的安全边界（为什么这不是「绕过」）

| 入口 | 正式玩家路径 | 说明 |
|:--|:--|:--|
| 快捷键/UI | 不存在 | 没有任何按键或界面能切换到 legacy |
| UI 协议命令 | 不存在 | 协议只有 `tech/submit|submit-all|track`；没有 set-mode/set-state 命令 |
| 游戏内脚本 | 不存在 | 游戏代码里没有读取页面全局的玩家路径 |
| 验收脚本 | 存在（唯一途径） | 需要在页面加载前注入 `__II_TEST_FLAGS__` 并 reload；属于测试脚手架 |
| 效果 | 门控放行 + 历史套件 | 只用于复跑 P2-E1 之前的验收断言，不改变正式流程 |

> 结论：legacy 是**启动期测试配置**，不是运行时 API 或作弊入口；正式流程默认 player 模式，门控全开生效。
> 若后续不希望长期保留，可在 E2/E3 把旧脚本全部迁移到 player 流程后删除（需另行授权）。

## 6. 待验收确认的决策

1. **起步包替换**：正式开局从 69 件（56+9+4）降为 21 件，接口盒/结构框架/核心复制改为科技解锁——这是 E0 设计的核心变化，请验收确认。
2. **legacy 兼容模式**：当前保留给旧验收脚本；是否在 E2/E3 后删除，需后续决定。
3. **飞轮配方简化**：E0 §4.9 的「10 铁锭 + 2 齿轮24」在运行时只有单输入能力，E1 实现为「12 铁锭」；节点交付成本（2 齿轮24+2 轴+3 铁锭）未变。
4. **调试件去留**：测试动力源/冲压机已从正式流程移除、代码保留；是否在 M3 清理需后续决定。
5. **矿石/成本平衡**：E0 预算要求提高矿量（约 210–250 铁锭当量 vs 当前 80），E1 未调整，属于 E3。
