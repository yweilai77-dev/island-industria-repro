# ISLAND INDUSTRIA · Roadmap v1.1（候选）

> 状态：**候选版本**（2026-11-07 起草于 M1 收官阶段）。定稿前需完成 M1.8 调查并与用户确认。
> 性质：这是**游戏产品层面的开发路线**，不是比赛官方规则。比赛章程（评分规则、提交格式、
> 截止日期）尚未拿到；拿到后必须把评审标准逐项映射到本路线，不得把本文件当成官方要求。

## 0. 一句话定位

在一座小岛上，玩家亲手搭建一座会真实转动的机械工厂。

## 1. 核心结论

第一交付物是**比赛级可玩 Demo**，不是无限扩张的工业系统。

- M1 做核心玩法（让游戏真正玩起来）→ 目标 L2。
- M2 做游戏体验完整度（让游戏像一款游戏）→ 目标 L3。
- M3 扩展工业深度，M4 扩展长期世界；两者不是参赛前置条件。
- M5 把经过验证的内容整理为比赛交付 → 目标 L4。

机械系统是 ISLAND INDUSTRIA 的核心特色，但在 Demo 成熟度里只是其中一项。

## 2. 目标完成度等级

| 等级 | 定义 | 标准 | 责任阶段 |
|:--|:--|:--|:--|
| L1 | 技术可用 | 系统运行、测试通过 | M1 全程 |
| L2 | 玩法成立 | 玩家能实际操作并完成闭环 | M1 结束 |
| L3 | 游戏完整 | 有内容、目标、反馈、视听表现和必要功能 | M2 结束 |
| L4 | 比赛交付 | 独立试玩稳定，展示效果与交付材料完整 | M5 结束 |

## 3. 八个验收维度

Demo 成熟度按这八项一起评审，不只看机械系统。

| # | 维度 | L2 最低线 | L3 目标 | 主责阶段 |
|:--|:--|:--|:--|:--|
| 1 | 世界与视觉表现 | 有可辨认的世界（地面/地形轮廓），建筑与机械能区分 | 岛屿地形、海岸线、远景天空、材质区分、统一美术风格、光照阴影氛围 | M2 |
| 2 | 玩家体验与基础操作 | 移动/视角/交互/采集/放置/拆除全部可操作且有反馈 | 无需开发者解释即可上手，按键提示明确，操作有节奏与容错 | M1 收尾 / M2 |
| 3 | UI 与交互设计 | 有 HUD、快捷栏、背包，能完成物品与建造操作 | 统一字体/图标/颜色/间距；建造菜单、机械状态、生产信息；选择/悬停/确认/取消反馈；信息分层 | M2 |
| 4 | 核心玩法深度 | 自由建造 + 亲手组装机械 + 动力沿结构传递 + 负载影响运行 + 机器有实际用途 + 产物反哺建造 | 同左，且至少一条完整生产链可重复运转 | M1 收尾 |
| 5 | 内容与游戏目标 | 玩家知道第一步做什么（可先靠引导文本） | 初始目标、新手引导、至少一条完整生产链、逐步解锁/扩张理由、短中期目标 | M2 |
| 6 | 音效与氛围 | 关键动作有声音 | 环境风声海浪、采矿/建造/拆除、轴/齿轮/飞轮/机器运转、完成/故障/过载提示、背景音乐与音量设置 | M2 |
| 7 | 完整性与稳定性 | 无严重崩溃/卡死，正常玩完一个闭环 | 主菜单、开始/退出、暂停、设置、操作说明、存档读档、状态一致、性能稳定 | M1 收尾 / M2 |
| 8 | 比赛展示与辨识度 | 能用一句话说清游戏是什么 | 一段完整可展示流程、一座标志性工厂、截图/演示视频/项目介绍 | M2 后期 / M5 |

## 4. 里程碑路线

### M1 · 核心玩法原型（进行中）

目标：让游戏真正玩起来。交付等级：L2。

- [x] 资源采集、库存与建造（M1.1–M1.4）
- [x] 三维空间与多层建筑（M1.5–M1.6；现状限制见 §7）
- [x] 机械结构、动力、齿轮与负载（M1.7-A/B/C）
- [ ] 跨层传动
- [ ] 正式动力源与首条生产链

### M2 · 游戏体验与内容完善（下一系列）

目标：让游戏像一款游戏。交付等级：L3。

- 岛屿环境、地形、材质、美术风格。
- 建筑与机械模型、动画和特效。
- HUD、背包、建造菜单和交互体验统一。
- 音效、环境声和音乐。
- 新手引导、任务和游戏目标。
- 存档、主菜单、暂停和设置。
- 完善首个 Demo 的实际内容量。

### M3 · 工业体系扩展（后续系列）

目标：让核心玩法有深度。

- 多种动力来源与工业技术发展。
- 复杂机械传动和工业设备。
- 更多资源、材料和加工工艺。
- 输送带、物品运输和自动供料。
- 多条生产线和自动化控制。

### M4 · 世界扩展与长期玩法（远期规划）

目标：让游戏可以长期玩下去。

- 更大规模的岛屿和资源区域。
- 工业区规划和物流。
- 电力等新的技术体系。
- 经济、订单、贸易或经营。
- 更丰富的科技发展与长期目标。

### M5 · 比赛 Demo 最终交付（最终里程碑）

- 全面质量检查。
- 性能、稳定性和兼容性优化。
- UI、美术、音效最终统一。
- 新手流程和展示流程测试。
- 演示视频、截图、项目介绍和交付包。

## 6. 质量线：每个阶段双门验收

1. **技术门**：`forgeax project check`、`pnpm test`、`pnpm typecheck`、构建、端到端 playthrough
   全部通过；playthrough 截图逐张看过。
2. **体验门**：不看代码、不看开发者说明，从启动开始完整玩一段；按 §3 八维打分；
   截图/录像留档。
3. **规则**：技术门全绿 **不等于** 阶段完成；先过体验门，才宣布阶段完成。
   这是 M1 阶段最重要的教训——不能出现“几百个测试通过，打开仍像工程测试场地”。

## 7. 当前技术约束（决策记录）

这些是当前代码的既定事实，M2 若要改必须显式决策：

- 视角：八方向俯视（45° 一档，Q/E 旋转，滚轮缩放，跟随玩家）；无跳跃/重力，WASD 平面移动。
- 尺度：1 格 1m；标准层高 3m；机械零件高 1m、占 1×1 格；地图 32×32m。
- 机械动力：单动力源、树状网络、拒绝闭环、极简扭矩模型（速度下垂 + 分支/整网过载停止）；
  无惯量、无摩擦、无动态负载。
- 多层：当前只有固定平台（level 1 @ y=3）和固定楼梯可达；玩家自建建筑不提供支撑面、
  不阻挡玩家。跨层传动尚未实现（无垂直轴/锥齿轮）。
- 存档：未实现，所有状态在内存，刷新即重置。
