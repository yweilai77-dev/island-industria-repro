# 性能预算（M1.8 调查）

> 目的：先定预算，再让 M2/M3 的资产与工厂规模在预算内增长；避免"大型工厂做出来才发现掉帧"。
> 当前场景很小，真正的风险在未来 10 倍实体量，所以本文以"每个工厂规模档位"给上限。

## 1. 当前基线（2026-11-07 实测）

| 指标 | 数值 | 来源 |
|:--|:--|:--|
| 分辨率 / 帧率 | 1280×720，稳定 **60 FPS** | playthrough 截图左上角宿主 FPS 计数 |
| 场景实体量 | 地面 + 4 段包边 + 4 处矿簇 + 平台/楼梯 + 若干建筑/机械，**< 100 个实体** | 场景包 + 运行截图 |

## 4. 已知性能风险点（按严重度）

1. **3D 读数/数字用 Box 实体拼装**：每个数字 7 段、每张读数卡十多个 Box；工厂里多台机器
   同屏时实体与 draw call 线性增长。→ M2 改为 DOM 覆盖层或合并网格。
2. **每台机器/零件独立实体与材质**：玩家自建规模上去后 draw call 增长。→ 需要实例化/合批
   或按材质合并（M3 前必须解决）。
3. **阴影距离 40m**：地图 32m 时够用；M4 扩岛后阴影级联与 shadowDistance 需重算。
4. **每帧重建 UI 状态消息**：UI 桥按 revision 发全量快照，实体多时会成为 CPU 热点（当前量小）。
5. **采集/建造每帧射线检测**：目前只对建筑/零件遍历，规模大时需要空间索引加速
   （已有 `SpatialIndex`，但拾取仍在遍历 Map）。
6. **冷启动**：`openMs 8.5s` 包含 dev 宿主；发布包需单独测，若 > 4s 要查资产加载与 shader 编译。

## 5. 测量方法（M2 要补齐）

1. **帧率**：前端用 `zaohua-platform-sdk.fps.start({ intervalMs, onStats })` 采样，
   记录 avg/min/max；导出到 `.forgeax/diag/`，不进 `artifacts/`。
2. **渲染统计**：用 `renderer.inspect()` 读 pipeline/资源统计（字段以 SDK 文档为准），
   记录 draw calls / 三角形 / 纹理内存。
3. **规模压测**：脚本生成 N 个零件/建筑的工厂（S/M/L 三档），各跑 60s，输出帧率曲线。
4. **首屏**：发布包本地起服务，记录 `loaded` 时间（不含 dev 宿主）。
5. **验收**：每次里程碑结束跑一遍 S/M 两档，截图 + 数字入库到 `docs/PROGRESS.md`。

## 6. 优化顺序（到了预算再动手，不提前优化）

1. 读数/数字 HUD → DOM 覆盖层（去掉大量 Box 实体）。
2. 机械零件/建筑按材质合批或实例化。
3. 阴影：按距离裁剪、远处不投影。
4. 拾取：用空间索引替代全表遍历。
5. 资产：纹理图集、合并小网格。
